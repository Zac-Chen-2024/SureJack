# 重选开头 —— 方案

**目标**:片子烧好之后,用户觉得开头几个画面不好看,想换一批,
**不该为此重烧整条**(现在 9 分半的片子要烧 14 分钟)。

**做法**:把开头切出来单独烧,后半段原样复用。

---

## 1. 边界由字幕决定,不由排布决定

### 规则(用户定的)

1. **算目标**:比例 × 配音总时长
2. **取大**:往后找**第一句结束时刻 ≥ 目标**的字幕行 —— 宁可长一点,不能短
3. **那一句的句尾就是边界**。开头 = 第 1 句 ~ 第 N 句

### 为什么锚在字幕上

词级时间戳在**配音完成那一刻就定死了**,之后永不改变。所以这个边界是
**确定性的、不可动摇的** —— 后半段能被永久复用,不是靠我们小心翼翼地
保持某个数值,而是因为它锚在一个本来就不会变的东西上。

而"比例 × 总长"是排布算法算出来的数,算法一改、素材一变就可能漂。

### 对齐句末的真正理由

**让后半段从「下一句话的开头」开始**,观众感觉不到接缝 ——
而不只是为了拼接技术上正确(技术上其实不需要:后半段是原样切下来的,
字幕已经烧在像素里,拼起来天然连续)。

### 实测(她那四条片子)

| 项目 | 目标 | 取大后的边界 | 多出 | 开头最后一句 → 后半段第一句 |
|---|---|---|---|---|
| 周周隐婚 | 78.0s | 第 84 句 **78.17s** | +0.15s | 「没有再跟我争辩,」→「他只是说:」 |
| 周周抢婚 | 110.7s | 第 123 句 **110.73s** | +0.00s | 「别等我跟池妄婚礼都办完了,」→「你们还没回来,」 |
| 周周双子 | 94.5s | 第 109 句 **95.00s** | +0.50s | 「刚要分开,」→「一双手扣在我的后脑上,」 |
| 周周小雨 | 101.4s | 第 106 句 **101.97s** | +0.54s | 「纪宸下颌绷得很紧,」→「那我真去了,」 |

最多只多 0.54 秒,每一处都断在一句话讲完的地方。

## 2. ⚠️ 最大的设计障碍:开头段现在不是定长的

```
开头段实际时长 = min(27% × 总长, 挑选素材的总时长)
```

铺不满时**缺口顺延给下一段**(`plan.ts` 的 `carry`,规则 4),而不是在开头桶
里循环。她挑了 6 个素材共 78 秒,而 27% 的目标是 152 秒 —— 所以开头只有 78 秒。

**于是换一批素材,开头就变长变短,后面全部平移。** 实测:

| 挑选 | 开头段时长 |
|---|---|
| 当前那 6 个 | 78.0s |
| 换一批 6 个 | **72.5s** ← 同样 6 个,差 5.5 秒 |
| 挑 12 个 | 152.2s(=27%,素材够了才顶到目标) |

### 解法:**挑不够就不让确认**

开头桶必须**正好铺满到边界**。素材不够时:

> ❌ 不循环补齐 —— 同一个片子重复播,一眼就看出是凑数的
> ✅ **告诉用户还差多少秒,让他接着挑**

时机正好:挑开头这一屏在**配音完成之后**,那时边界已经算得出来。
界面上实时显示「已选 62 秒 / 需要 78 秒,还差 16 秒」,凑够了才能确认。

铺的时候按挑选顺序依次放,**最后一个片子截断**到正好落在边界上——
这正是 `fillFrom` 现在的行为,不用改。

> ⚠️ 边界情况:整个开头桶(68 个片段)加起来都不够长。理论上可能,
> 实际上开头段只占 27%(10 分钟的片子约 2.7 分钟),68 个片段远远够。
> 真碰上就退回原来的 carry 逻辑并记日志——不能让用户卡在挑选界面出不去。

### ⚠️ 但这会改变现有项目的排布

老项目的开头现在是 78 秒;改了规则就变成填满 152 秒 → 完全不同的片子
→ `masterFingerprint` 变 → **开机补合会把它们全部重烧**。

**必须做隔离(carve-out)**:新规则只对**有 `head_boundary_ms` 的项目**生效。
老项目那一列是 NULL,走原来的 `carry` 逻辑,指纹逐字节不变。

这和"字幕上限 17→14 用 LEGACY_SUBTITLE_MAX_CHARS 隔离"是同一个套路。

## 3. 数据

新增一列 `head_boundary_ms INTEGER`(可空):

- **NULL** = 老项目 / 还没配音 → 走原逻辑,不支持重选开头
- **有值** = 开头边界的毫秒数,**配音完成那一刻算好写死,之后永不改**

为什么必须落库而不是每次现算:比例常数以后可能会调,现算的话老项目的
边界会跟着漂,后半段就复用不了了。落库 = 一次算定,终身有效。

---

## 4. 指纹拆两份

现在一个 `masterFingerprint` 管整条。拆成:

```
headFingerprint = 开头素材清单 + 边界 + [0, 边界) 内的字幕和样式
tailFingerprint = 边界 + [边界, 结尾) 的排布 + 字幕 + 样式
```

- **只有开头变** → `tailFingerprint` 不变 → **后半段可复用**
- 文案/字幕/配音变 → 两个都变 → 整条重烧(本来就该)

`masterFingerprint` 保留不动(整条的身份,给补合和归档用)。

---

## 5. 烧录时必须在边界强制关键帧

实测母带关键帧平均 **7.7 秒**一个,边界处**没有** —— 不强制就切不出干净的
后半段(`-c copy` 只能从关键帧切)。

烧录命令加 `-force_key_frames <边界秒数>`。代价极小(多一个 I 帧)。

⚠️ **只有带这个标记烧出来的母带才能被无损切开**。之前烧的片子没有那一帧,
重选开头时只能整条重烧 —— 这一点要在代码里显式判断,不能假设。

---

### 实测(2026-08-15,540×960 / fast / crf21 / 30fps,和母带同参数)

| 测的东西 | 强制了关键帧 | 没强制(= 加这个功能之前烧的片子) |
|---|---|---|
| 分界处有关键帧吗 | **有**,正好 7.500 | 没有。最近的在 8.333 |
| `-ss 7.5 -c copy` 切出的后半段 | 375 包 = 12.5s × 30fps,**正好** | **600 包**,首包 pts = **−7.5** |
| 后半段第一帧 vs 原片那一帧 | **SSIM 1.000000**(逐像素一致) | 0.977 |
| 拼回去之后 | 20.000s / 600 包 / DTS 单调 / 解码无错 | 20.000s 但 **825 包** |

⚠️【失败的样子看不出来】。没强制关键帧时 ffmpeg 会退到前一个关键帧(这里是 0.0),
把整条都搬进"后半段",再用 edit list 把起点标到 7.5 —— **时长元数据仍然是 20.000 秒**。
拼出来的文件比应有的多 225 帧(7.5 秒的旧开头),而进度条、时长、ffprobe 的 format
全都正常。只有真播才看得出来。所以 `keyframeForced` 必须记的是**事实**,不能靠推断。

接缝实测:第 7.50 秒那一帧与原片同一时刻 SSIM = 1.000000,第 7.40 秒还是新开头的画面
(SSIM 0.42)—— **切口干净,不多一帧不少一帧**。

## 6. 重选开头的流程

```
1. ffmpeg -ss <边界> -i master.mp4 -c copy tail.mp4     几秒，无损
2. 烧新的开头 head.mp4（只烧那 78 秒）                    约 2 分钟
3. ffmpeg -f concat -c copy → master.mp4                 几秒，无损
```

**平时不额外占存储** —— 后半段是从现有母带里切出来的,不是常驻的第二份。
只有真的重选时才多切一刀。

对比:整条重烧 14 分钟 → **约 2 分钟**。

---

### 实测(2026-08-15,端到端换头,真烧真拼)

用代码里【真实的】烧录参数烧一条 20 秒带字幕的母带,再真的换掉开头:

| | 原母带 | 换头后 |
|---|---|---|
| 时长 / 帧数 | 20.000000s / **600 帧** | 20.000000s / **600 帧** |

后半段逐像素比对(**含烧进去的字幕**):

| 时刻 | SSIM |
|---|---|
| 7.50s(接缝那一帧) | **1.000000** |
| 9.00s | **1.000000** |
| 13.33s | **1.000000** |
| 19.90s(片尾) | **1.000000** |

开头确实换掉了:1.00s → 0.383,7.40s → 0.405。整条解码**无错无警告**。

### 头段长度必须精确到毫秒

烧录原来用 `-t (ms/1000).toFixed(1)`,只精确到 0.1 秒。头段照这个烧会比分界
长/短最多 50 毫秒 ≈ 1.5 帧,而后半段是从分界那一毫秒切下来的——**后面整条
字幕就相对配音偏移**,而且从接缝一直错到片尾。所以新增 `exactDuration`,
只有换头这条路用三位小数;整条烧录那条路一个字都没动(改了会让重烧出来的
片子和从前差一帧)。

### 两段的编码参数由代码结构保证一致

concat demuxer 是流级拼接,两边参数只要有一处对不上,**轻则报错,重则拼出
一个只有前半段能正常播的文件而时长还是对的**。所以编码参数抽成
`MASTER_VIDEO_ARGS` 一个常量,整条烧录和换头共用同一份。

## 7. 全局冲突检查

| 关注点 | 结论 |
|---|---|
| 老项目会不会被重烧 | **不会**。新填充规则靠 `head_boundary_ms` 隔离,老项目那一列是 NULL |
| 之前烧的片子能不能重选开头 | **不能**(没有强制关键帧)→ 代码要显式判断并退回整条重烧 |
| 预览(HLS) | 母带变了要重新切,和现在一样 |
| 成片(deliver) | 母带指纹变 → 待取成片自然过期,下次下载重混。已有机制 |
| 归档 | 归档删母带 → 重选开头前要先复原。要给出明确提示 |
| 续集 | 续集的排布只用开头桶 + 跑酷桶,比例是 [1,0,0] —— 边界逻辑同样适用,但要单独验 |
| 自备 SRT(line 模式) | 字幕是句级的,边界照样能算。但那条路没有"开头桶"概念,**不支持重选** |

## 8. 分批实施

### 第一批:边界的纯函数 + 测试
`headBoundary(lines, totalMs, ratio)` → `{ lineIndex, endMs }`。
纯函数、无 IO,先把"取大"和确定性钉死。

### 第二批:落库 + 排布按边界填充
加列;`planProjectBackground` 接受显式的开头时长;开头桶铺满到边界为止
(最后一片截断)。**carve-out**:没有边界的项目走原逻辑。
挑选接口返回"需要多少秒",不够时拒绝确认并说清还差多少。

### 第三批:烧录强制关键帧 + 指纹拆分
`-force_key_frames`;`headFingerprint` / `tailFingerprint`。

### 第四批:重选开头的接口和流程
切 → 烧 → 拼;失败要能退回整条重烧。

### 第五批:前端入口
成片页给一个「重选开头」,复用现有的挑选界面。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 改填充规则误伤老片 | carve-out + 上线前逐条比对 `masterFingerprint` |
| 拼接处有可见跳变 | 边界对齐句末;两段用**完全相同的编码参数**;先做一次真实拼接肉眼验收 |
| 切点不在关键帧 → 后半段前几帧花屏 | 烧录时强制关键帧;切完 `ffprobe` 校验第一帧是 I 帧 |
| 开头桶素材太少 | 挑不够不让确认,界面实时显示"还差多少秒"。**不循环补齐**——重复播同一个片子一眼就看出是凑数的 |
